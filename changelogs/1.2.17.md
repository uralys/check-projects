# v1.2.17 - 2026-06-08

## Improvements

### Revamped `make tag` workflow

`make tag` now prepares a release in one command, and the changelog history has been brought back in sync.

**What's New**:

- `make tag` now generates the changelog, runs the test suite, builds the binary, commits the changelog and creates the tag
- The changelog is scaffolded from `feat`/`fix` commits since the last tag (or an existing handwritten file is used as-is)
- `changelogs/index.md` is updated automatically with the new version entry
- Pushing stays manual: the script prints the exact `git push --follow-tags` command to run when you are ready
- Backfilled the missing changelogs for v1.2.13 through v1.2.16 and refreshed the index

**Impact**: Tagging a release is now a single, safe command that guarantees tests pass, the build succeeds, and the changelog is in sync before the tag is created — while you keep full control over when it is pushed.
